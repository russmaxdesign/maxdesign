What’s the difference between :focus and :focus-visible?

Published: 18 September 2026

:focus

:focus matches whenever an element has focus, regardless of how that focus was received: through the keyboard, a pointer interaction, or a script calling .focus().

In the example below, every focused button gets a visible ring, including after a user clicks it (in browsers where clicking gives the button focus).

.btn:focus {
  outline: 3px solid #005fcc;
  outline-offset: 2px;
}

Strengths:

  • Works everywhere, including very old browsers.
  • Completely predictable and easy to test: if an element has focus, the focus styles apply.
  • Can benefit people using speech recognition, switches, or other input methods where a persistent focus indicator provides useful orientation.

Weaknesses:

  • Can show a focus ring after a pointer interaction, which some designers prefer to avoid. This often tempts people to remove it with outline: none, which also removes it for keyboard users unless another visible indicator is provided.
  • Can look visually noisy on click-heavy interfaces, especially on large tiles or cards.

:focus-visible

:focus-visible matches when the browser decides that a visible focus indicator should be shown. It makes this decision based on things such as the input method and the type of element receiving focus.

Browsers already use this logic for their own built-in focus styles.

When you tab to a button, you usually see a focus ring. When you click it, you usually don’t.

.btn:focus-visible {
  outline: 3px solid #005fcc;
  outline-offset: 2px;
}

Strengths:

  • Avoids showing a focus ring for most pointer interactions while retaining a visible keyboard focus indicator.
  • Matches the behaviour users commonly see from browser default focus styles.
  • Browser rules usually keep the indicator for elements such as text fields, where focus needs to be clear before typing.

Weaknesses:

  • The behaviour is decided by the browser rather than entirely by your CSS. Browsers can differ around edge cases, and their rules may change.
  • Pointer users who benefit from seeing where focus moved may not receive a visible indicator immediately after clicking or tapping.
  • Very old browsers don’t support it, so you may need a fallback if they’re still in scope. For most projects, this is no longer an issue.
  • Can be harder to test. If no indicator appears, that may be expected behaviour or it may be a problem.
  • When a script moves focus, whether the indicator appears can depend on the browser and the interaction that led to the focus change.

Demo

  1. Press TAB to move through the buttons in each group. Both look the same.
  2. Now click a button in each group. The :focus group shows a ring, the :focus-visible group doesn't.
  3. Click a button in the :focus-visible group, then press Tab. The next button shows a ring, because you're now using the keyboard.
  4. Click into the Name field in each group. Both show a ring, because browsers keep the indicator for text fields.

Using Safari on a Mac? Press Option+Tab instead of Tab. Step 2 won’t show a difference in Safari, because clicking a button doesn’t give it focus. Try Chrome or Firefox instead.

Wrap-up

In most cases, :focus-visible is a sensible default. Use :focus where you want the indicator to always appear.

Whatever approach you use, make sure the focus indicator is easy to see, with sufficient contrast against adjacent colours.
