Do screen readers announce “bullet” when a list uses list-style: none?

Published: 05 January 2026

This article uses a simplified, browser-centric explanation to describe observed behaviour across the DOM, accessibility tree, and screen readers.

If you remove bullets from an unordered list using list-style: none, do screen readers still announce “bullet” before each list item?

At first glance, this feels like a screen reader question.

But the answer actually lives deeper in the browser pipeline:

  • How browsers generate list markers.
  • How those markers are represented internally.
  • How CSS can prevent markers from being generated.
  • How this affects what appears in the accessibility tree.
  • How that ultimately influences screen reader speech output.

To explore this, we’ll start with a simple unordered list:

  • Red
  • Green
  • Blue
<ul>
  <li>Red</li>
  <li>Green</li>
  <li>Blue</li>
</ul>

The ::marker

The bullets associated with each list item are not represented as nodes in the DOM. Instead, they are generated by the browser as ::marker pseudo-elements as part of list item layout.

If we inspect the list above in Chrome or Firefox’s DevTools, the generated visible structure looks conceptually like this:

<ul>
  <li>
    ::marker
    "Red"
  </li>
  <li>
    ::marker
    "Green"
  </li>
  <li>
    ::marker
    "Blue"
  </li>
</ul>

This representation reflects how some browsers expose the generated marker for debugging purposes, not a structure defined by the HTML or CSS specifications.

The accessibility tree

If we look at Chrome’s accessibility tree, we can see that each ::marker is represented as a ListMarker node (for example, with the text "• " for a default unordered list).

Conceptually, this looks like:

list ""
  listitem ""
    ListMarker "• "
    StaticText "Red"
  listitem ""
    ListMarker "• "
    StaticText "Green"
  listitem ""
    ListMarker "• "
    StaticText "Blue"

In Firefox’s accessibility tree, list markers are represented in a similar way, as a list item marker with a name of "• ".

list: ""
  listitem: "• Red"
    list item marker: "• "
    text leaf: "Red"
  listitem: "• Green"
    list item marker: "• "
    text leaf: "Green"
  listitem: "• Blue"
    list item marker: "• "
    text leaf: "Blue"

Because the marker exists, browsers have something they can expose to assistive technologies.

Screen reader output (default list styling)

With default list styling, screen readers typically announce both the list structure and the bullet.

While actual screen reader output may vary depending on a range of factors, it could be something like:

VoiceOver

  • <ul>: “List 3 items”
  • First <li>: “Bullet Red 1 of 3”

NVDA

  • First <li>: “List with 3 items Bullet Red”

JAWS

  • <ul>: “List 3 items”
  • First <li>: “Bullet Red”

What happens when we set list-style: none?

Now let’s add list-style: none to the list:

  • Red
  • Green
  • Blue
<ul style="list-style: none;">
  <li>Red</li>
  <li>Green</li>
  <li>Blue</li>
</ul>

When this style is applied, browsers do not generate a list marker box, and no ::marker pseudo-element is created for the list item.

If we inspect the list above in Chrome or Firefox’s DevTools, the generated visible structure now looks conceptually like this:

<ul>
  <li>
    "Red"
  </li>
  <li>
    "Green"
  </li>
  <li>
    "Blue"
  </li>
</ul>

There is no marker to hide. It is not created.

The accessibility tree (with list-style: none)

Because the marker is no longer generated, there are no list item marker nodes in Chrome or Firefox’s accessibility tree. The marker information is gone before assistive technologies are involved.

In Chrome, the list now this looks something like:

list ""
  listitem ""
    StaticText "Red"
  listitem ""
    StaticText "Green"
  listitem ""
    StaticText "Blue"

And in Firefox, the list now this looks something like:

list: ""
  listitem: "• Red"
    text leaf: "Red"
  listitem: "• Green"
    text leaf: "Green"
  listitem: "• Blue"
    text leaf: "Blue"

Screen reader output (with list-style: none)

With the markers removed, screen readers still announce the list structure, but no longer announce “bullet” before each item.

As before, the actual screen reader output may vary depending on a range of factors. But it could be something like:

VoiceOver

  • <ul>: “List 3 items”
  • First <li>: “Red 1 of 3”

NVDA

  • First <li>: “List with 3 items Red”

JAWS

  • <ul>: “List 3 items”
  • First <li>: “Red”

This is not a screen reader choice to suppress bullets. The marker information is no longer generated by the browser, so it cannot be exposed.

Key takeaway

list-style: none does more than change how a list looks.

By preventing browsers from creating a list marker box, it removes information before it ever reaches the accessibility tree.

Screen readers can only announce what the browser exposes. In this case, the bullet no longer exists as exposed information.

Caveats

This article describes observed browser behaviour using Chrome and Firefox as examples, rather than defining requirements of the HTML or CSS specifications.
