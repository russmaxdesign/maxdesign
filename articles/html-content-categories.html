HTML content categories

Published: 30 December 2025

If you have worked with HTML for a long time, you may have heard elements described as “block-level” or “inline.”

These ideas came from earlier specifications and CSS defaults. They describe presentation of elements, but not their meaning.

Modern HTML, defined in the HTML Living Standard, groups elements into content categories.

These categories do not control how elements look. They describe how elements fit into the document structure and how they relate to the elements around them.

Content categories do not decide where an element may be used or which elements it may contain. Those rules are defined separately in the specification under each element’s content model and permitted contexts.

In this article, we focus on the categories that matter most for everyday authoring. We are not covering every edge case or specialised category here.

Overview of content categories

The HTML Living Standard defines a range of element categories, including:

  • Metadata
  • Flow
  • Sectioning
  • Heading
  • Phrasing
  • Embedded
  • Interactive
  • Palpable content
  • Script-supporting

These categories are not hierarchical. They do not stack or inherit from one another.

Some elements belong to zero categories

The following elements are not currently assigned to any of these categories. Their permitted usage is still fully defined in other areas of the specification:

<html>, <head>, <body>, <li>, <dt>, <dd>, <figcaption>, <source>, <track>, <caption>, <colgroup>, <col>, <tbody>, <thead>, <tfoot>, <tr>, <td>, <th>, <optgroup>, <option>, <legend>, <summary>

Some elements fall into multiple categories

For example, the <a> element can fall into several:

  • Flow content
  • Phrasing content
  • Interactive content (when it has an href attribute)
  • Palpable content (when it contains content users can perceive, like text or images)

Let’s take a quick look at some common category examples:

1. Flow content

Most elements that appear in the <body> belong to flow content. These elements form the main structure of the document.

In the example below, the <div> and <p> are flow content, while <span> is phrasing content:

<div>
  <p>Paragraph</p>
  <span>Span</span>
</div>

2. Phrasing content

Phrasing elements represent text and the markup that appears within text. In most cases, only other phrasing content may appear inside them.

In the example below, the <span> and <em> are phrasing elements. The <div> is a flow element, so it cannot be placed inside a phrasing element as shown here.

<span>
  <em>Valid phrasing</em>
  <div>Non-conforming</div>
</span>

3. Heading content

Heading content represents headings for sections of content.

This category includes: <h1>, <h2>, <h3>, <h4>, <h5>, <h6> and <hgroup> (when it contains at least one heading element).

For accessibility, use HTML heading elements rather than styling text to look like headings. Avoid placing non-phrasing content inside them. Many screen readers allow users to navigate by heading to move efficiently through a page.

In the example below, the <h1> is a heading. The bold text is only a visual style.

<h1>This is a heading</h1>
<p><b>This is a visual style, not a heading</b></p>

When headings are used inside sectioning elements like <article> or <section>, they help express the structure of the document. Headings outside sectioning elements still provide meaningful navigation for users and assistive technologies, even if they do not contribute to a structured outline.

<section>
  <h1>Heading inside a section</h1>
</section>

4. Interactive content

Interactive content includes elements designed for user interaction. These elements are usually focusable and can be activated with the keyboard, mouse, touch, or assistive technologies.

Examples include:

<a href="#">Link</a>
<button>Button</button>
<input type="text">
<select>...</select>
<textarea>...</textarea>
<details>...</details>
<audio controls></audio>
<video controls></video>
<img usemap="#mapname">

These elements are generally expected to:

  • be focusable (unless disabled or intentionally hidden)
  • support activation through keyboard and pointer
  • expose an interactive role to assistive technologies

Interactive elements cannot contain other interactive elements

Certain interactive elements, such as <a> and <button>, do not allow other interactive controls as descendants. Nested controls can create conflicting focus and activation behaviour.

These patterns are non-conforming:

<a href="#">
  <button>Invalid nested button</button>
</a>

<button>
  <a href="#">Invalid nested link</a>
</button>

This pattern is also non-conforming because tabindex creates an additional focusable descendant:

<a href="#">
  <div tabindex="0">Focusable descendant</div>
</a>

Browsers may attempt to repair these structures, but behaviour is not consistent across browsers or assistive technologies.

Why this matters for accessibility

When controls are nested, users may experience:

  • unexpected focus order
  • duplicate or missing announcements from screen readers
  • activation issues (inner control triggers the outer control)
  • confusing hit targets on touch devices

Transparent content models

Some elements (such as <a> with an href) have a transparent content model.

Transparent is not a content category. It is a rule that affects permitted content.

Transparency means the element’s permitted content is determined by the context in which the element is used. In these cases, the parent element’s content model takes precedence.

In the example below, the <a> element can contain a <div> as the parent <article> allows flow content:

<article>  
  <a href="#">
    <div>Permitted here (flow is allowed)</div>
  </a>
</article>

In the example below, the <a> element cannot contain a <div> as the parent <span> allows phrasing content only:

<span>  
  <a href="#">
    <div>Non-conforming here (div is flow, not phrasing)</div>
  </a>
</span>

Transparent models do not override other rules. For example, nested interactive elements remain non-conforming regardless of context.

Conformance, validity, and browser repair

When talking about HTML, the spec uses a few related terms:

  • Conforming: The HTML follows all the rules. Nothing is out of place.
  • Non-conforming: The HTML can still be loaded, but it breaks one or more rules.
  • Invalid: The HTML is broken in a way that the browser cannot read without fixing it first.

Browsers will usually try to “fix” invalid or non-conforming HTML so the page still shows. This is called error recovery or browser repair.

However, these repairs are not guaranteed or consistent.

Screen readers and other assistive technologies may see a different structure than what the browser shows visually.

For accessibility, it’s safest to write HTML that doesn’t rely on repair behaviour.

Summary

Content categories provide a mental model for understanding how elements behave.

If you’re ever unsure, look up the element’s content model and permitted content in the HTML Living Standard. It’s the final source of truth for how HTML works.
