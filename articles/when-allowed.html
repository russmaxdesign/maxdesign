When are aria-label and aria-labelledby allowed for naming elements?

Published: 24 May 2026

aria-label and aria-labelledby are intended for elements whose roles support author-provided accessible names. These roles can be either implicit (native to the HTML element) or explicit (assigned via ARIA).

To understand this, we first need to understand roles.

What are roles?

Roles provide meaning to HTML elements so browsers and assistive technologies can understand what each element is and how it should behave.

For example, a role can identify an element as a:

  • button
  • heading
  • navigation
  • checkbox
  • dialog

Roles communicate the purpose and expected behaviour of elements to assistive technologies such as screen readers.

What are implicit and explicit roles?

Implicit roles are roles that HTML elements already have by default.

For example:

  • <button> has an implicit role of button
  • <nav> has an implicit role of navigation
  • <main> has an implicit role of main

Browsers automatically provide these roles without needing extra markup.

Explicit roles are roles added manually by authors using the role attribute.

In the example below, the <div> element is explicitly assigned the role of button.

<div role="button">Save</div>

What are accessible names?

Accessible names identify elements for assistive technologies such as screen readers. For example:

  • A button might have the accessible name “Save”
  • A search field might have the accessible name “Search”
  • A dialog might have the accessible name “Settings”

Accessible names can come from different sources, including:

  • visible text
  • <label> elements
  • alt attributes
  • aria-label
  • aria-labelledby

Whether an element can have an accessible name depends on its role.

Which roles can have names?

Many interactive and page-structure roles allow accessible names. Examples of roles that commonly allow names include:

  • button
  • link
  • checkbox
  • radio
  • textbox
  • heading
  • img
  • dialog

For example, a button role can have the name “Save”, and a dialog role can have the name “Settings”.

Some roles are not intended to represent meaningful content or interactive controls, so they do not allow accessible names. Examples include:

  • presentation
  • none
  • generic
  • separator (when not focusable)

In the example below, the element is treated as purely presentational, so giving it an accessible name would have no meaning.

<div role="presentation"></div>

This is why aria-label and aria-labelledby should only be applied to elements whose role supports naming.

Applying them to roles like presentation or generic is not supported by the ARIA specification, even though some browsers or assistive technologies may still expose names in certain situations.

Further reading

The rules above describe what the ARIA specification intends. In practice, browsers are often more tolerant than the spec requires. They sometimes expose accessible names even when they shouldn't.
