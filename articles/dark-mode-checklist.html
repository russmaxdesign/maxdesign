Dark mode checklist

Published: 14 September 2026

What is dark mode?

Dark mode is a display setting that uses darker background colours and lighter text and interface elements. It provides an alternative colour scheme for people who prefer it or find it more comfortable.

It is a complete colour scheme that can affect colours, images and other parts of an interface.

How does the system preference reach the page?

  1. The operating system has a light or dark appearance setting.
  2. The browser reads that preference and makes it available through prefers-color-scheme.
  3. CSS can then use that preference to apply light or dark styles.

It is important to remember that prefers-color-scheme only tells you what the user prefers. The site still needs to provide the corresponding styles.

This checklist

This checklist covers some of the most common things to check when reviewing a design or interface in dark mode.

Design

Set light and dark values for

  • page backgrounds
  • component and surface backgrounds
  • text, including secondary and muted text
  • links
  • borders and dividers
  • icons
  • form controls

Colours

  • Be careful with pure black backgrounds and pure white text

    Very high contrast can make text appear to glow or blur for some people, including people with astigmatism. Research on this effect in dark mode is limited, but using an off-black background with slightly softer text can help. Some people with low vision also find light text on a dark background easier to read, so the aim is to tune dark mode rather than avoid it.

  • Lighten and desaturate brand and accent colours

    Highly saturated colours that work well on a light background can feel too strong against a dark one.

  • Check status colours

    Error, warning and success colours should remain distinct and recognisable in dark mode.

  • Check contrast

    Text, icons, borders and controls should have sufficient contrast in both modes. The contrast calculation is the same in light and dark mode, but the colours differ, so check each mode separately.

  • Check states

    Hover, focus, active, selected, visited and disabled states should be checked in both modes.

Shadows and overlays

  • Shadows can be hard to see on dark surfaces. Consider using lighter surface colours to distinguish raised elements.
  • Check overlays and gradients to make sure they still work well against dark backgrounds.

Images and graphics

  • Check logos, illustrations, charts and diagrams against both light and dark backgrounds.
  • Check transparent images for unwanted light or dark edges.
  • Swap images if they don’t work in both modes:
<picture>
  <source srcset="logo-dark.svg" media="(prefers-color-scheme: dark)">
  <img src="logo-light.svg" alt="Example logo">
</picture>

Development

Tokens and variables

Avoid hard-coded colours.

  • Use semantic colour variables or design tokens:
color: var(--text-color);
background-color: var(--surface-color);
  • Make sure foreground and background colours change together. A colour without its matching background is a bug waiting to happen.
  • Avoid !important on colour declarations. It can make theme overrides harder to manage because later styles may also need !important, along with careful control of specificity and source order.

Declaring the colour scheme

Start by declaring the colour schemes your site supports, then choose how you want to provide the light and dark values.

Step 1: declare color-scheme

color-scheme tells the browser which colour schemes your page supports. This lets browser-provided elements, such as form controls and scrollbars, match the current scheme.

:root {
  color-scheme: light dark;
}

The first value is the preferred scheme and the second is also supported.

You can also declare the colour scheme in the <head>. Because the browser reads the meta element before the stylesheet loads, it can use the right page colour from the start.

<meta name="color-scheme" content="light dark">

Only declare schemes that the site actually supports. If you declare both light and dark, make sure your own colours and styles also work correctly in both.

Step 2: choose how to provide light and dark values

Option A: prefers-color-scheme

Use prefers-color-scheme to apply styles based on the user's system setting.

@media (prefers-color-scheme: dark) {
  /* dark mode styles */
}

Option B: light-dark()

light-dark() lets you provide a light value and a dark value together, without repeating them in a media query.

:root {
  color-scheme: light dark;
  --text-color: light-dark(#1a1a1a, #e6e6e6);
}

The first value is used for light mode and the second for dark mode.

light-dark() relies on color-scheme, so make sure Step 1 is in place when using it.

If using a toggle

  • If the control overrides the system setting, consider offering light, dark and system options so users can return to following their system preference.
  • Persist the user's choice.
  • Default to the system setting.
  • Give the control an accessible name and make its current state clear.

Things that may not follow the theme

  • Third-party embeds: maps, video players, payment widgets, captchas, iframes.
  • Syntax highlighting in code samples.
  • Background images and other assets designed for a light background.
  • Email templates and PDFs generated by the site.

Things that get missed

  • Styled form controls, including inputs, selects and checkboxes, as well as placeholder text.
  • accent-color on checkboxes, radios, range inputs and progress bars.
  • SVG fill and stroke values. Use currentColor where appropriate.
  • Pseudo-elements such as ::before and ::after.
  • Gradients, shadows and semi-transparent colours.
  • Print styles, which should not inherit the dark theme.
  • <meta name="theme-color"> for the browser interface. You can provide different colours for light and dark mode:
<meta name="theme-color" content="#ffffff" media="(prefers-color-scheme: light)">
<meta name="theme-color" content="#1a1a1a" media="(prefers-color-scheme: dark)">

Final check

Test all pages and components in both light and dark mode, including hover and focus states, form and validation states, and disabled and selected states.

Dark mode and forced-colours mode, such as Windows contrast themes (previously called High Contrast), work differently. A site that works well in dark mode may still have problems in forced-colours mode, so test both separately.

Most importantly, test with dark mode on a real device!
