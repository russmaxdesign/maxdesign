Tests for CSS generated content alternative text

Published: 28 December 2025

Sometimes, designers use CSS content: to add text or icons before or after elements. If that content is meant to be seen, it might also need an accessible version for people who can’t see it.

The spec allows you to add alternative text by putting it after a slash in the content property. For example:

.icon::before {
  content: "🔍" / "Search";
}

The part before the slash is what’s shown visually - in this case, a magnifying glass icon.

As per the CSS Generated Content Module Level 3 specification, the slash alternative text is intended as a replacement for speech output - in this case the speech output should be “Search”.

If such alternative text is provided, it must be used for speech output instead.

In supporting browsers, this alternative text may be exposed to the accessibility tree and could be used by assistive technologies in place of the visible CSS content.

Let’s look at four variations:

Test criteria:

For these tests, “announced” means that the exact string (for example, “Visible generated content” or “Hello world”) is spoken when the block receives focus. Partial or generic announcements like “and one other item” are treated as failures.

These tests distinguish between:

  • Keyboard focus navigation (e.g. using the TAB key)
  • Screen reader reading navigation (e.g. line-by-line or virtual cursor navigation)

Test cases

Test 1: Generated content only

This is example 1 
.test-old::after {
  content: "Visible generated content";
}

Pass criteria:

  • 1.1: "Visible generated content" should be announced.

Test 2: Alternative text only

This is example 2 
.test-alt-only::after {
  content: "" / "Hello world";
}

Pass criteria:

  • 2.1: Generated content should not be announced (left blank).
  • 2.2: "Hello world" alternative text should be announced when navigating via keyboard focus (TAB).
  • 2.3: "Hello world" alternative text should be announced when navigating line-by-line using a screen reader.

Test 3: Blank alternative text

This is example 3 
.test-visible-only::after {
  content: "Visible generated content" / "";
}

Pass criteria:

  • 3.1: "Visible generated content" should not be announced. Even though the value is blank, it is still considered alternative text as the slash and quotes are present.
  • 3.2: No generated or alternative text should be announced when navigating via keyboard focus (TAB).
  • 3.3: No generated or alternative text should be announced when navigating line-by-line using a screen reader.

Test 4: Generated content and alternative text

This is example 4 
.test-both::after {
  content: "Visible generated content" / "Hello world";
}

Pass criteria:

  • 4.1: "Visible generated content" should not be announced because the alternative text replaces this content.
  • 4.2: "Hello world" alternative text should be announced when navigating via keyboard focus (TAB).
  • 4.3: "Hello world" alternative text should be announced when navigating line-by-line using a screen reader.

Summary of findings

As support is still slightly inconsistent across browser and screen reader combinations, this syntax should probably be treated as experimental. For important information, continue to use semantic HTML and ARIA, and do not rely on CSS-generated content as the sole mechanism for accessibility.

Footnotes

  • 08/02/2026: Tests 3.1 and 4.1 were updated to align with the CSS specification’s replacement model for alternative text. The results were adjusted accordingly.
  • 08/02/2026: Additional tests added to determine different navigation methods.

Disclaimer

Test results involving operating systems, browsers, and assistive technologies should be interpreted with care. Behaviour can vary across versions, browser engines, and assistive technology settings, even when default configurations are used.
