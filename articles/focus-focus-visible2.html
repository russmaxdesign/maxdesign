Why doesn't the focus ring appear when I click?

Published: 18 September 2026

You click a button and no focus ring appears. Is that an accessibility failure? Usually not. It often comes down to whether the site uses :focus or :focus-visible to style focus.

This article explains the difference, lets you try both, and covers what to look for when testing.

What :focus does

:focus applies styles whenever an element has focus. It doesn't matter how the element got focus: from the keyboard, a mouse click, a tap, or a script.

With the rule below, every focused button gets a visible ring, including after someone clicks it (in browsers where clicking gives the button focus).

button:focus {
  outline: 3px solid #005fcc;
  outline-offset: 2px;
}

What :focus-visible does

:focus-visible applies styles only when the browser decides a focus indicator should be shown. It bases this on things like how the person is interacting and what type of element has focus.

In practice, when you Tab to a button, you see a ring. When you click it, you usually don't. Browsers already use this same logic for their own built-in focus styles.

button:focus-visible {
  outline: 3px solid #005fcc;
  outline-offset: 2px;
}

Because the browser makes the decision, behaviour can vary a little between browsers.

Try it yourself

The two groups below use exactly the same focus ring. The only difference is the selector. The buttons don't do anything when activated.

  1. Press Tab to move through the buttons in each group. Both groups look the same.
  2. Now click a button in each group. The :focus group shows a ring. The :focus-visible group doesn't. This is expected, not a failure.
  3. Click a button in the :focus-visible group, then press Tab. The next button shows a ring, because you're now using the keyboard.
  4. Click into the Name field in each group. Both show a ring, because browsers keep the indicator for text fields.

Using Safari on a Mac? Press Option+Tab instead of Tab to move between buttons. Step 2 won't show a difference in Safari, because clicking a button doesn't give it focus. Try Chrome or Firefox for that step.

What to look for when testing

Test focus with the keyboard

If no focus ring appears after you click a button, that's usually expected. WCAG 2.4.7 Focus Visible requires a visible indicator when using a keyboard, not after every click.

A missing ring with the keyboard is the real problem

You don't need to know which CSS was used. If you Tab to an element and can't see where focus is, that's an issue, whatever the cause.

Check the ring is easy to see

A faint or thin indicator can be almost as bad as none. Under WCAG 1.4.11 Non-text Contrast, it needs at least 3:1 contrast against adjacent colours. Check it in dark mode too, if the site supports it.

Text fields usually show a ring, even on click

If clicking into a text field shows no indicator, it's worth a closer look.

Watch what happens when focus moves on its own

Some patterns move focus for you, such as dialogs, error summaries and skip links. Open them with the keyboard and check that you can see where focus lands. Then try the mouse. A missing ring after a click isn't a failure on its own, but it can leave people unsure where they are.

Test in more than one browser

Browsers decide when :focus-visible shows a ring, and they don't always agree. If something looks odd in one browser, check another before reporting it.

Consider other input methods

Voice commands often behave like mouse clicks, so people using speech recognition may not see a ring when :focus-visible is used. This isn't a failure, but it can be worth noting in a report as a usability observation.

Wrap-up

No focus ring after a click is usually expected behaviour, not a bug. Test with the keyboard first, and make sure the focus indicator is easy to see, with sufficient contrast against adjacent colours.
